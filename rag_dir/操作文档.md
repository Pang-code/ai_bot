# RAG 文档处理流水线操作文档

本文档说明 `rag_dir/` 下从 PDF 到可向量化切片 (chunks.json) 的完整处理流程。

```
PDF ──batch_parse.py──> md + images ──describe_images.py──> 图文融合版 md ──chunk_md.py──> chunks.json
       (MinerU 转换)                  (VLM 识别图片内容)                     (标题级切片)
```

## 目录约定

```
rag_dir/
├── compose.yaml               # MinerU 服务 (端口 8080 -> 容器 8000)
├── batch_parse.py             # 步骤 1: PDF -> Markdown
├── describe_images.py         # 步骤 2: 图片内容识别并回写 md
├── chunk_md.py                # 步骤 3: Markdown 切片
├── auto_parse_monitor.py      # 监控脚本 (可选)
└── doc/
    ├── huawei_doc/            # 文档集 1: 华为产品手册
    ├── common/                # 文档集 2: 通用文档 (法律/员工手册/设备手册等)
    └── output/                # MinerU 任务输出 (中间产物, uuid 目录)

doc/<文档集>/md/               # 流水线工作目录 (每个文档集一份)
├── image_descriptions.json    # 步骤 2 的描述缓存 (断点续传)
└── <文档名>/
    ├── <文档名>.md            # 图文融合版 md (唯一数据源)
    └── images/*.jpg           # MinerU 解析出的图片
```

> 注意: md 只保留子目录一份 (`md/<文档名>/<文档名>.md`)，它与 `images/` 同目录，
> md 内的相对路径 `images/xxx.jpg` 才有效 (本地打开可正常看图)。不要在 `md/` 根下另放 md。

## 前置条件

1. **Docker Desktop 已启动** (步骤 1 依赖; 批量处理期间务必保持运行,
   电脑休眠/Docker 重启会导致容器中断, 脚本虽会自动重试但应尽量避免)
2. **uv 虚拟环境可用** (项目根 `.env/`, 依赖见 pyproject.toml)
3. **`.env` 已配置 VLM 渠道** (步骤 2 依赖):

   ```
   VLM_API_KEY=<视觉模型 key>
   VLM_BASE_URL=<OpenAI 兼容接口地址>
   VLM_MODEL=<视觉模型名>          # 当前: agnes-3.0-flash
   ```

   > OpenRouter 免费档仅 50 次/天, 不适合批量; 换渠道只需改这三个变量。

## 步骤 1: 启动 MinerU 服务

```bash
cd rag_dir
docker compose up -d        # 首次会构建镜像 local/mineru-pipeline:3.4.1-cpu (较久)
```

健康检查 (浏览器打开看到 FastAPI 界面即正常):

```bash
open http://localhost:8080/docs
```

查看日志 / 停止:

```bash
docker compose logs -f mineru-api
docker compose down
```

## 步骤 2: PDF 转 Markdown (batch_parse.py)

```bash
uv run python rag_dir/batch_parse.py                          # 默认处理 doc/huawei_doc/
uv run python rag_dir/batch_parse.py --input-dir doc/common   # 处理其他文档集
uv run python rag_dir/batch_parse.py -i doc/common -o doc/common/md   # 显式指定输入输出
```

**输出** (每个 PDF 三个产物):

| 文件 | 用途 |
|---|---|
| `md/<stem>.md` | 纯文本版 (无图标签) |
| `md/<stem>/<stem>.md` | 带图版 (内含 `images/xxx.jpg` 引用) |
| `md/<stem>/images/*.jpg` | 解析出的图片 |

**特性**:
- 断点续传: 已有非空输出的 PDF 自动跳过, 中断后直接重跑同一条命令
- 容错: 单个 PDF 最多 4 轮重试 (提交/轮询/拉取), 服务重启会自动等待恢复 (最长 900s)
- 日志: `batch_parse.log`

## 步骤 3: 图片内容识别 (describe_images.py)

对 md 中引用的每张图片, 提取其**所属章节标题 + 前后文窗口**作为上下文,
与图片一起发给视觉模型生成中文描述, 然后**回写 md**:

```markdown
<!-- 回写前 -->
![](images/ffa6a225....jpg)

<!-- 回写后 -->
[图片: 该图为笔记本各视角的部件示意图, 以数字标注摄像头、麦克风...](images/ffa6a225....jpg)
```

```bash
uv run python rag_dir/describe_images.py rag_dir/doc/huawei_doc/md
uv run python rag_dir/describe_images.py rag_dir/doc/common/md
```

**特性**:
- 断点续传: 描述缓存于 `md/image_descriptions.json`, 重跑只处理缺描述的图
- 共享调用: 相同图片文件 (内容 hash 同名) + 相同章节共享一次 VLM 调用
- 限速处理: 429 自动等待重试 (每张最多 5 次)
- 幂等: 已回写的 md 中原始标签已消失, 重复执行无副作用; 无描述的标签保留原样, 重跑可重试
- 产出统计: 结束时打印 "替换 N 处图片标签 / 实际调用 M 次"

## 步骤 4: 切片 (chunk_md.py)

```bash
uv run python rag_dir/chunk_md.py rag_dir/doc/huawei_doc/md
uv run python rag_dir/chunk_md.py rag_dir/doc/common/md
uv run python rag_dir/chunk_md.py path/to/单文件.md   # 单文件调试
```

**切片策略** (参数: `CHUNK_SIZE=800`, `CHUNK_OVERLAP=80`):
1. 预处理: 删除"目录"章节; `</tr>` 展开为独立行 (超长表格按表格行边界切, 不截断单元格)
2. 图片: 描述文本 `[图片: ...]` 保留在 text 中参与 embedding;
   图片路径剔除出文本, 提取进 `metadata.images` (供前端展示原图)
3. 按 `#`/`##` 标题切 section; 超过 800 字符的用 RecursiveCharacterTextSplitter 二次细切
   (切点优先级: 空行 > 换行 > 句号 > 分号 > 逗号), 相邻块 80 字符重叠
4. 丢弃纯标题空壳

**输出** `<文档集>/chunks.json`, 每个 chunk:

```json
{
  "text": "## 快捷键功能介绍 ...",
  "metadata": {
    "source": "<文档名>.md",
    "product": "<产品型号>",
    "section": "快捷键功能介绍",
    "images": ["images/xxx.jpg"],
    "chunk_index": 6,
    "global_index": 6
  }
}
```

## 常见问题

| 现象 | 处理 |
|---|---|
| 批量转换中途 Docker 中断 | 直接重跑同一条 batch_parse 命令 (已完成的自动跳过) |
| describe_images 报 429 | 正常限速, 脚本自动等待; 频繁 429 建议换 VLM 渠道 |
| 某图片描述为空 | 重跑 describe_images 即可 (空描述的标签仍保留原始格式, 会被重试) |
| chunks.json 需要重新生成 | 直接重跑 chunk_md.py (幂等, 不依赖 VLM) |
| 新增/更新了部分 PDF | 从步骤 2 开始按序重跑, 各步骤均有断点续传 |
